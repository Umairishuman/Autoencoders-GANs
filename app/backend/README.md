# Restoration Lab — backend (FastAPI + ONNX Runtime)

Serves the four assignment workspaces from the exported ONNX models. **No PyTorch at inference time.**
Corruptions are generated by `src/pet_data.py`, the same module that produced the training,
validation and test corruptions, so the app's "apply corruption" matches the training pipeline exactly.

## Run

```bash
# from the repository root, with the ONNX files in ./models
docker compose up --build            # -> http://localhost:8000/docs

# or without Docker (Python 3.11)
pip install -r backend/requirements.txt
PYTHONPATH=src:backend uvicorn app.main:app --app-dir backend --port 8000
```

Required files in `models/`:
`task1_universal_dae.onnx`, `task2_classifier.onnx`, `task2_expert_salt_pepper.onnx`,
`task2_expert_gaussian_blur.onnx`, `task2_expert_occlusion.onnx`, `task3_soft_moe.onnx`,
`task4_face2sketch_generator.onnx` (+ the optional `.json` sidecars shown on the System page).
Sample images: put a few clean pet photos in `backend/samples/pets/` and face photos in `backend/samples/faces/`.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | status, which models are loaded, warm-up latency |
| GET | `/api/models` | model files, I/O shapes, sidecars (hyper-parameters, ONNX parity, test metrics), W&B link |
| GET | `/api/samples?kind=pets\|faces` | bundled sample images; `GET /api/samples/{kind}/{name}` returns one |
| POST | `/api/corrupt` | preview a corruption (no model) |
| POST | `/api/restore/universal` | **Task 1** universal autoencoder |
| POST | `/api/restore/hard` | **Task 2** classifier → identity bypass or one specialist |
| POST | `/api/restore/soft` | **Task 3** soft MoE: 4 weights, each branch's own output, optional hard-routing comparison |
| POST | `/api/sketch` | **Task 4** photo + style `0`/`1`/`2`/`all` → sketch(es) |

Restoration endpoints take `multipart/form-data`:

| field | values |
|---|---|
| `file` **or** `sample` | uploaded image, or a sample name |
| `corruption` | `none` (image already corrupted), `clean`, `salt_pepper`, `gaussian_blur`, `occlusion` |
| `severity` | `low` / `medium` / `high` (fixed test severities), `random` (training distribution), `custom` |
| `p`, `kernel_size`, `sigma`, `n_boxes`, `coverage`, `seed` | custom parameters; `seed` makes a corruption reproducible |
| `compare_hard`, `include_branches` | soft endpoint only |

Responses contain PNG data URLs (`images.input`, `images.output`, and, when a corruption was applied to a clean image,
`images.reference` and `images.error_map`), quality metrics (PSNR/SSIM/MAE vs the clean reference), the exact corruption
parameters, routing information and timings (`timing_ms`: preprocess, per-model inference, total).

Errors: `400` missing input, `404` unknown sample, `413` file too large, `415` not an image, `422` invalid parameters,
`503` model not loaded. All return `{"error": ..., "detail": ...}`.

## Implementation notes
* Preprocessing mirrors training: `convert('RGB')` → 128×128 bicubic → /255 (faces: transparency composited on white).
* All models are loaded once at start-up and warmed up; sessions are thread-safe, endpoints run in FastAPI's thread pool.
* The soft-MoE graph's internal tensor `/moe/Concat_output_0` (the stacked branch outputs, `torch.stack` in `moe.py`) is exposed
  as an extra output at load time, so the UI can show each branch's contribution. No retraining or re-export is needed, and
  the test suite checks that Σ wₖ·branchₖ reproduces the model output.

## Tests
```bash
cd backend && PYTHONPATH=../src:. pytest -q      # 19 tests against the real ONNX models
```
They cover every endpoint, equality with direct onnxruntime calls, corruption = `pet_data` output, mixture
consistency, style differences, and the error cases.
